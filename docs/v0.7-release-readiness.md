# v0.7 release readiness review

Review basis: feature branch commit `ac9e2ad` (2026-09-24). This records
evidence against the required gates in
[`v0.7-developer-product.md`](v0.7-developer-product.md), section 19. It is
not a release approval. The package metadata still declares `0.6.0`.

## Evidence available

| Gate group | Evidence and status |
| --- | --- |
| C1–C6 correctness | Facade tests cover dispatch reservation, recovery, eligibility, replay, verification, and reconciliation; architecture mapping is in the [public API](v0.7-public-api.md). Code review of the full release candidate remains to be recorded. |
| D2–D3 experience | Quickstart and three disposable scenarios print Decision, adapter observation, verification, Effect, and Warrant information; examples run in the installed wheel CI job. |
| D1 author rehearsal | On 2026-09-24 the project author created a fresh temporary Windows venv, installed the source checkout with `pip install -e .`, ran `examples/sqlite_delete.py` and `cage example database.delete`, and observed `ADMITTED`, `ACKNOWLEDGED`, `VERIFIED_BOUND`, and `BOUND` in both runs. Python was 3.13.2 and `[System.Environment]::OSVersion.VersionString` reported `Microsoft Windows NT 10.0.26200.0`. The reported elapsed time was 0.22 minutes. This was an author rehearsal using provided PowerShell commands, not an unfamiliar developer following the published Quickstart independently. |
| D4, S4, O2 integration boundaries | [Integration guide](integration-guide.md) describes public adapter/verifier contracts, target correlation, recovery, local state ownership, and trust limits. |
| O3, P1–P2 CLI and portability | `cage --help`, `--version`, all three `example` commands, and Warrant inspect/validate are exercised in tests or CI. Portable format v1 and disclosure are specified in the public API document. |
| K2–K3 Windows and packaging | The package job builds a wheel and sdist, checks packaged resources, installs the wheel outside the checkout, and invokes its examples and CLI. On 2026-09-24, a Windows PowerShell run built `cage_assurance-0.6.0-py3-none-any.whl`, installed it into a fresh temporary venv outside the checkout with `pip install --no-index --no-deps`, ran `cage --version`, all three `cage example` commands with Warrant export and validation, and all four packaged scripts. The user reported the final `Windows wheel check passed` message. This establishes a Windows wheel smoke check; the Python version and Windows version were not printed in that run. |
| K1 static compatibility | Comparing the v0.6.0 tag with the current feature branch source on 2026-09-24 found all 18 baseline `src/cage/core` modules still present and no removals among their 44 public top-level classes and functions. None of the 222 baseline `test_*` functions in the 18 baseline test files was removed or renamed (the v0.6 release reported 279 collected test cases). A follow-up AST comparison found no changed argument lists, defaults, or annotations among public top-level functions and public methods of public classes in those core modules. The v0.6 package-root `__init__.py` contained no public exports; v0.7 adds root imports. On Python 3.13.2 in Windows NT 10.0.26200.0 the user reported 492 passing tests on the feature branch at `adb7fdc` plus this documentation-only review. This supports source and tested-behavior compatibility; it is not a comparison of every external integration or installed v0.6 wheel. |
| Python CI | [Run 36052009650](https://github.com/roopamwsure/cage/actions/runs/36052009650) passed tests on Python 3.11, 3.12, 3.13, and 3.14, plus the package job, for commit `2104114`. CI runners are Ubuntu; this is not a multi-OS matrix. |

## Required work still open

| Gate | Needed before calling v0.7 release-ready |
| --- | --- |
| D1 | An unfamiliar developer must follow the published Quickstart without author assistance. Record elapsed time, environment, and friction; confirm the under-15-minute target after Python prerequisites. Automated example runs do not establish this. |
| D4–D5, S1–S3 | Review integration guide against real adapter/verifier implementation, inspect negative-path diagnostics and default disclosures, and record release-candidate test evidence for each gate. A passing suite alone is not a completed gate review. |
| K1–K2 | Confirm the retained baseline tests and public imports on the final release candidate and document migration for any difference. Publish only OS/Python combinations actually checked; the separate Windows wheel run did not print interpreter or OS versions. |
| L1 | The [semantic guide](semantic-guide.md) and [portable Warrant and CLI guide](portable-warrants-and-cli.md) now cover state meanings, inspection, exit codes, and format compatibility. Review both against the release candidate and check every runnable documentation command against the release wheel. |
| API contract | The public API design proposed `IdentityConflictError`, but known pre-dispatch override conflicts currently raise `CAGEValueError`. Decide whether the specialization is required, then align implementation and docs before claiming that exception as public. |
| L2 | Record gate-by-gate decisions, package version/changelog, diff, and clean status. Review repository `LICENSE`, `SECURITY.md`, `CONTRIBUTING.md`, release documentation, dependency provenance, and history before any public release or distribution action. Those repository files are not present at this review commit. |
